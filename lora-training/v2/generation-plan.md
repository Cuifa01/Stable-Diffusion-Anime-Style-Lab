# Myonstyle v2｜候选图生成与筛选方案

> 记录日期：2026-11-09  
> 状态：**首轮 24 张小样本已完成并记录分析；下一轮尚未实施**。本文不是已验证有效的正式批量生成配置。

## 1. 目标与边界

- 目标：为 **Myonstyle v2 画风 LoRA** 筛选能体现人物面部、发丝、线条、明暗与阴影风格的高质量图片，而不是训练特定角色或场景。
- 总体目标流程：**250 张候选 → 人工筛选 120 张 → 100 张训练 + 20 张保留检验**。
- **不混入 v1 现有的 45 张**。
- 先完成小样本测试，再决定是否调整组合配额、删除不稳定变量或补充定向样本。
- 已有资料仍作为基础，不覆盖：
  - `lora-training/v2/prompt-framework.md`：原始 Prompt 结构、固定风格块、负面词与 NeoForge 参数。
  - `lora-training/v2/character-outfit-bindings.md`：12 位角色及服装/发型绑定（含未核实的草稿项）。

## 2. 当前已确认的设计决策

1. **场景与角色绑定**：不再将 11 个环境模块作为独立随机池与所有角色自由组合；每个角色有 1–2 个符合其视觉形象的主题场景。
2. **保留简洁背景作为对照**：暂以约 **80% 角色主题场景 / 20% 简单背景** 为工作假设，**比例未经实验验证**，也不是每个角色必须严格执行的硬配额。
3. **动作不可省略**：动作需与景别、人物在画面中的占比配合，不再统一仅用 `dynamic pose`。
4. **远距离全身像质量风险较高**：当前模型在人物过远时容易丢失脸部及服饰细节。因此 `full body` 仅作为待测试的少量候选，优先测试紧凑坐姿/蹲姿；不能为了满足“景别覆盖”把低质量图纳入训练。
5. **人脸优先**：侧面、背身回望、低机位等构图，必须以人脸清晰可见、眼部与发丝细节足够为前提。
6. **每张保留原始 Positive Prompt**，并记录自动打标结果与二者差异，便于错误筛查及后续定向补图。
7. **机器差异分数只负责提示复核，不直接删图**：WD14 或其他 tagger 对光照、视角、动作、场景细节等标签可能漏检或误判。

## 4. 其他变量（保留可变）

### 时间与光照

- 时间：`daytime` / `sunset` / `night`。
- 光照：`soft lighting` / `cinematic lighting` / `dramatic lighting`。
- 不做盲目笛卡尔积：室内/数字空间未必适合每种自然时间，森林夜间不得沿用 `sunlight filtering through trees`；背景、时间、光照之间不能相互矛盾。

### 视角（6 种）

- `front view`
- `three-quarter view`
- `(from side:1.2)`
- `from above`
- `from below`
- `(from behind:1.2), looking back`（`looking back` 必须绑定）

背身回望不与 `close-up` 强行组合；侧面/背身/极端视角需特别检查脸部质量。

### 景别、画幅与动作

- 景别候选：`close-up` / `upper body` / `cowboy shot` / `full body`。
- 画幅由 **NeoForge Width × Height** 控制，而不是写入 `portrait`/`landscape` Prompt：
  - 竖图：**832 × 1152**
  - 横图：**1152 × 832**
- **动作与景别绑定的测试方向**（不是经验证的固定 Danbooru 标签池）：

| 景别 | 优先尝试 | 注意事项 |
| --- | --- | --- |
| `close-up` | 轻微歪头、正视镜头等 | 不堆复杂手部动作 |
| `upper body` | 前倾、自然坐姿、手托脸等 | 脸部、头发和上身细节优先 |
| `cowboy shot` | 坐姿、二郎腿、轻微前倾 | 注意双腿是否合理 |
| `full body`（限制数量） | 蹲姿 `squatting`、鸭子坐 `wariza`、盘腿坐 `sitting cross-legged`、二郎腿 `crossed legs` | 尽量提高人物在画面内占比，**不强求远距离站立全身像** |

> `crossed legs`、`sitting cross-legged` 与 `wariza` 分别指不同坐姿，不应混用。最终是否保留取决于实际生成质量；即使姿势正确，脸部细节不足的图也不应进入训练集。

### 表情（5 种）

- `gentle smile, closed mouth`
- `smile, open mouth`
- `expressionless, closed mouth`
- `surprised, open mouth`
- `one eye closed, smile, closed mouth`

眨眼与夸张表情宜少量出现，不应损害眼睛及面部细节覆盖。

## 5. Prompt 组装原则

- 继承 `prompt-framework.md` 中原有的分段 `BREAK` 顺序、固定画风串、质量词、负面词、NeoForge/ADetailer/Hires.fix 参数；**本文不覆盖或擅自改写该文件**。
- 原始框架里的 `[ ]` / `{ }` 是文档讨论标记，不是提交给 NeoForge 的字面 Prompt 内容。
- 角色身份、发型、服饰、场景和动作应置于原框架对应内容位置；不把全部模块平铺为一段。
- 原框架最后的固定背景示例含 `simple background`、`white background`、`sky`、`sunset`、`soft lighting` 等内容；实际组装动态场景时**必须移除或替换冲突元素**，不能机械叠加。
- 所有提交给生成器的任务须保留**实际最终完整 Positive Prompt**，不能仅保存变量名或模板。Negative Prompt 继续作为固定生成参数使用，**不需要额外输出或展示**。

## 6. 图像留档、自动打标与筛选

每个生成任务应有唯一 `image_id`，且原始图片与 sidecar 文件可通过相同 ID 关联；至少保留：

- `img_001.png`：生成图。
- `img_001_positive.txt`：生成时实际使用的**完整 Positive Prompt**。
- `img_001_meta.json`：角色、主题场景、时间、光照、视角、景别、动作、表情、画幅、seed、参数和实际生成状态。
- `img_001_tags.txt`：WD14 或现有 tagger 的检测标签；打标失败需写明状态，不得伪造。
- `img_001_compare.json`：预期视觉标签、检测标签、匹配/缺失/额外标签、分数、疑似问题及需要复核的原因。

汇总层面应提供：

1. **Manifest（CSV/JSON）**：记录每行生成任务与执行结果，支持重新生成或定向补图。
2. **对比报告**：按角色、场景、动作、视角、景别聚合缺失标签与异常情况。
3. **Contact Sheet**：显示缩略图、ID、角色、Prompt 摘要及疑似异常，供人工筛选。
4. **样本覆盖统计**：区分“计划生成”“成功生成”“机器提示异常”“人工通过”“进入训练/检验”，避免把缺标签当作实际样本缺失。

**筛选顺序**：生成并留档 → 自动打标 → 文本对比并标记风险 → 人工检查画面和人脸细节 → 保留合格样本 → 根据各类缺口定向补图。**不得仅凭文本差异自动删除原图。**

## 9. 首轮 24 张试运行｜简要实验分析（2026-11-10 记录）

**实验标识**：`run_20261109_221810`。来源：本地 `summary_report.md`、`manifest.csv`、24 份 Positive Prompt / compare JSON、Contact Sheet。**这一轮仍是旧的随机场景方案，不是角色专属场景方案的验证。**

| 项目 | 结果 |
| --- | --- |
| 生成 | 24/24 成功 |
| 自动打标 | 24/24 完成；实际使用 **JoyCaption**，不是 WD14 |
| `flagged` | 19/24（79.2%），是文本比对风险标记，**不是 19 张坏图** |
| 异常理由 | `character_tag_missing=16`；`environment_no_overlap=12`，两者可重叠 |
| Recall 阈值 | 低于 0.20 才触发该项；24 张均未低于阈值（最低 0.286） |

**发现与判断（区分机器结果和视觉初看）：**

1. **打标比对误报风险大**：JoyCaption 的角色名称、背景描述未必与原 Prompt 精确一致。应改为按人物外观、场景、姿势、景别等组分别核对，并保留同义词/不确定标签；机器结果仅提示复核，不据此自动删图。
2. **Prompt 结构不符合既定模板**：24 个 Positive Prompt 均只有 **5 个 `BREAK`**；动作与视角/景别合并了。下次恢复原先独立动作段（共 6 个 `BREAK` 分隔），其他固定词及 NeoForge 参数仍按原框架。
3. **视觉初看**：部分远距离站立全身像、极端低机位或俯身构图导致人脸过小/细节不足；`full body`、`close-up` 等标签也不保证真实构图准确。保留紧凑坐姿、蹲姿、鸭子坐、盘腿、二郎腿等**待测试方向**，优先人物占比与面部细节。
4. **场景偏离角色形象**：部分随机背景不符合预期角色氛围，支持**下一轮测试角色专属场景**的必要性；尚不能证明新方案一定更好。
5. **留档流程可沿用**：Positive Prompt、Manifest、自动标签、比对 JSON、Contact Sheet 有助于定位问题及定向补样。

**后续执行决定：**

- **这一轮不再耗费太多精力逐张人工处理**，保留记录供参考，不把它视为已筛出的训练样本。
- **取消独立 Negative Prompt 输出**（例如 `img_001_negative.txt`）；不在交付报告重复列出 Negative Prompt。**只是取消输出，不是取消生成时的固定负面词。**
- 继续保留每图 **完整 Positive Prompt**、标签及差异结果、必要的任务元数据和总览图。
- 下一轮优先验证：**角色—场景绑定、动作—景别绑定、完整 `BREAK` 结构，以及打标/比对的可靠性**；正式 250 张配额暂不冻结。
